     ---

     AWS Study Buddy — Spec

     Goal

     A one-page flashcard app for learning AWS services. Each card shows a
     service name. Pressing "Show answer" reveals one plain sentence on what the
     service does, a short category, and a link to its official AWS
     documentation.

     Constraints

     - Plain HTML, CSS and JavaScript. No frameworks, no npm packages, no build
       step.
     - It opens by double-clicking index.html (a file:// URL). No server and no
       installs.
     - Because of that, cards.js is loaded with a classic <script 
       src="cards.js">, not an ES module, since browsers block modules over
       file://.

     Files

     ┌────────────┬──────────────────────────────────────────────────────┐
     │    File    │                       Purpose                        │
     ├────────────┼──────────────────────────────────────────────────────┤
     │ index.html │ Page markup. Loads style.css, cards.js, then app.js. │
     ├────────────┼──────────────────────────────────────────────────────┤
     │ style.css  │ Styling.                                             │
     ├────────────┼──────────────────────────────────────────────────────┤
     │ app.js     │ Card display and navigation logic.                   │
     ├────────────┼──────────────────────────────────────────────────────┤
     │ cards.js   │ The card data, and nothing else.                     │
     ├────────────┼──────────────────────────────────────────────────────┤
     │ check.js   │ Data validator, run with node check.js.              │
     └────────────┴──────────────────────────────────────────────────────┘

     Card data (cards.js)

     - Declares one global array: const CARDS = [ ... ];
     - Ends with if (typeof module !== "undefined") module.exports = CARDS; so
       Node can require it. Browsers ignore this line.
     - Each card is an object with exactly these fields, all strings:
       - service: the service name, e.g. "Amazon ECS"
       - answer: one plain sentence saying what the service does
       - category: a short free-text label, e.g. "Containers"
       - docsUrl: the official docs page, starting with
         https://docs.aws.amazon.com/
     - Starter cards, in this order:
       a. Amazon ECS: Containers: https://docs.aws.amazon.com/AmazonECS/latest/d
          eveloperguide/Welcome.html
       b. AWS IAM: Security:
          https://docs.aws.amazon.com/IAM/latest/UserGuide/introduction.html
       c. Amazon Bedrock: AI / Machine Learning: https://docs.aws.amazon.com/bed
          rock/latest/userguide/what-is-bedrock.html

     App behaviour

     - On load, the page shows the first card's service name with the answer
       hidden.
     - Show answer reveals the sentence, the category and a docs link. The link
       opens in a new tab (target="_blank" rel="noopener").
     - Next and Previous move through cards in cards.js order. Next on the last
       card goes to the first, and Previous on the first card goes to the last.
     - Changing cards hides the answer again.
     - A position indicator shows where you are, e.g. "Card 2 of 3".
     - If CARDS is missing or empty, the page says "No cards found" instead of
       breaking.

     Check script (check.js)

     Run with node check.js. It loads ./cards.js with require and checks:
     1. cards.js loads without error and exports an array.
     2. Every card has all four fields: service, answer, category and docsUrl. A
        field only counts as missing when its key is absent or its value is not
        a string.
     3. No service name appears twice. The comparison ignores case, trims the
        ends and collapses inner whitespace, so "Amazon S3" and " amazon  s3"
        count as the same.
     4. Every docsUrl starts with https://docs.aws.amazon.com/.

     Output:
     - If everything passes, it prints PASS and exits with code 0.
     - Otherwise it prints FAIL, then one line per problem naming the card
       (index and service name, where known) and what is wrong, and exits with
       code 2. It reports every problem, not just the first one.

     Done when

     - [ ] Double-clicking index.html in Chrome, Safari or Firefox shows the
       first card, with no console errors.
     - [ ] Show answer reveals the sentence, the category and a working docs
       link for all 3 starter cards.
     - [ ] Next and Previous cycle through all 3 cards and wrap at both ends.
       The answer hides again on each move.
     - [ ] node check.js on the starter data prints PASS and exits 0.
     - [ ] Each of the following prints FAIL plus the specific problem and exits
       2: removing a field from a card, adding a second "amazon ecs", and
       changing a docsUrl to http://example.com.
     - [ ] Several problems at once are all listed.
     - [ ] The project has no package.json and no node_modules, and makes no
       network calls except the docs links the user clicks.

     Not now

     - More than 3 cards
     - Shuffle, random order, or spaced repetition
     - Scoring, progress tracking, or "I knew it / I didn't" buttons
     - Saving state between visits (localStorage)
     - Search, filters, or browsing by category
     - Keyboard shortcuts and flip animations
     - Rejecting blank-string fields, unknown extra fields, or categories
       outside a fixed list
     - Checking that docs links actually resolve (no network calls in check.js)
     - Hosting, deployment, and automated browser tests

     - Open SPEC.md and confirm that both the "Done when" and "Not now" sections
       are present.
     - Confirm the three docs URLs start with https://docs.aws.amazon.com/.

  File: app.js

    textContent, so card data can't inject HTML. If CARDS is missing or empty,
    the page shows "No cards found" and the buttons are disabled.
  ────────────────────────────────────────

  What goes in it: Loads ./cards.js inside a try/catch, so a broken file reports

    card checks the four fields are present strings, collects normalised service

    checks each docsUrl starts with https://docs.aws.amazon.com/. Every problem
    goes into one list, then it prints PASS and exits 0, or prints FAIL plus one

    line per problem and exits 2.

  check.js will also report a card that isn't an object at all (for example null
  or a string) as a problem, instead of crashing on it.

  changing.
